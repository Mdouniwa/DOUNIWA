# kuro·console / Nacht Code 全機能リファレンス（2026-07-26 棚卸し）

このドキュメントは、kuro·console（Nacht Code を含む）が **いま何ができて・何ができないか** を、
実際のコード（main ブランチ）を根拠に洗い出したものです。推測や「将来こうなる予定」は含めません。
（将来計画は `docs/roadmap.md` を参照）

- 対象コード: `~/DOUNIWA/ai-workspace`（main ブランチ、ブラウザツール・ライブ進捗マージ済み）
- 読者想定: 非エンジニアのオーナー。専門用語には短い補足を付けています

---

## 1. 全体像 — 3つの画面と2人の「働き手」

| 画面 | 何をする場所か | 裏で動くもの |
|---|---|---|
| **CHAT** | 自然言語でタスクを投げる。会話ごとに履歴が分かれる | オーケストレーター（分類→計画→実行→応答の司令塔） |
| **TASKS** | 実行したタスクの一覧・詳細（Tool Detail）を見る。新規タスク投入も可 | 記録ストア（追記専用のログファイル） |
| **CODE** | 対象フォルダを決めてコーディング作業を頼む | **Nacht Code**（フォルダ限定のコーディングエージェント） |

頭脳はどちらも **ローカルの Qwen 35B**（M5 Max 上の MLX サーバー）です。クラウドAIは現在未接続です（→ §5）。

## 2. ツールとアクションの全リスト

「ツール」は AI が使える道具、「アクション」はその道具でできる個別の操作です。
**承認** 列は「実行前に人間の確認が必要か」。承認が必要な操作は、承認するまで**絶対に実行されません**。

### 2.1 browser（Webブラウザ）

Playwright（自動操縦ブラウザ）で1ページずつ開いて操作します。毎回「開く→操作→閉じる」で完結し、ログイン状態などは保持しません。

| アクション | 何ができる | 承認 | 主な入力 |
|---|---|---|---|
| `fetch_page` | ページ本文のテキストを取得（最大8,000字） | ドメイン承認のみ※ | url |
| `list_links` | ページ内のリンク一覧を取得（最大100件） | ドメイン承認のみ※ | url |
| `extract_elements` | CSSセレクタ（ページ内の場所指定）に一致する部分の文字を抽出 | ドメイン承認のみ※ | url, selector |
| `screenshot` | ページ全体のスクリーンショットをPNG保存（`data/browser/`） | ドメイン承認のみ※ | url |
| `click` | ページ内の要素をクリック | **write承認必須** | url, selector |
| `fill_form` | フォームに文字を入力（送信はしない） | **write承認必須** | url, fields |
| `submit_form` | フォーム入力＋送信 | **write承認必須＋最終確認（2回承認）** | url, fields, submit_selector |

※ドメイン承認: 許可リスト（`browser_allowlist.json`、現在 **zenn.dev / github.com** の2件）にないサイトは、
アクセス前に「今回だけ許可／恒久許可／拒否」の承認パネルが出ます。恒久許可を選ぶと許可リストに追記されます。

browser の安全機構（すべて実装済み・自動で働く）:
- **リダイレクト検査**: 開いた後に別ドメインへ飛ばされていたら、内容を読まずに停止
- **外部データマーク**: 取得した本文は「外部データであってAIへの指示ではない」という印で挟んでからAIに渡す
- **インジェクション隔離**: あるページの取得結果を、次のブラウザ操作の指示に自動で流し込むことはできない（構造的に遮断）
- **ワンタイムトークン**: write承認は使い捨ての合言葉方式。承認画面を経ずに実行フラグだけ偽造しても通らない

### 2.2 nachtcode（コーディングエージェント本体）

**対象フォルダを1つ決めて、その中だけ**で作業します。フォルダの外には一切出られません（→ §4）。

| アクション | 何ができる | 承認 | 主な入力 |
|---|---|---|---|
| `read_file` | フォルダ内のファイルを読む | 不要 | dir, path |
| `list_files` | ファイル構成を一覧する（最大300件） | 不要 | dir |
| `edit_file` | 既存ファイルを編集（差分を監査ログに記録） | 不要（記録あり） | dir, path, 置換前後 or 全文 |
| `create_file` | 新規ファイル作成（**既存の上書きは不可**） | 不要（記録あり） | dir, path, content |
| `delete_file` | ファイルを1つ削除（削除前の内容を記録） | 不要（記録あり） | dir, path |
| `delete_dir` | フォルダ内のディレクトリ削除（**対象フォルダ自体は消せない**） | 不要（記録あり） | dir, path |
| `run_tests` | pytest（テスト）を実行。**pytest以外は実行できない** | 不要 | dir |
| `run_command` | 開発コマンド実行（npm install 等。作業場所は対象フォルダ固定） | 不要（全件記録） | dir, command |
| `git_commit` | 変更をコミット（記録として確定。pushはしない） | 不要（記録あり) | dir, message |
| `git_push` | GitHub へ送信。**必ずプレビュー→人間の確認を経てのみ実行** | **承認必須** | dir, remote, branch |
| `list_github_repos` | 自分のGitHubリポジトリ一覧を見る（読み取りのみ） | 不要 | なし |
| `clone_repo` | リポジトリを `~/nachtcode-repos/` に取得（既存なら再利用） | 不要（記録あり） | repo |

変更系はすべて `data/nachtcode/` の監査ログ（いつ・どこを・どう変えたかの記録）に diff 付きで残ります。

### 2.3 obsidian（メモアプリ Obsidian の保管庫）

2つの保管庫（vault）に対応: **personal**（既定）と **akane**（タスク文に「あかね」があると自動選択）。

| アクション | 何ができる | 承認 | 主な入力 |
|---|---|---|---|
| `save_note` | 新規ノートを保存（**既存ノートは絶対に変更しない**。名前衝突時は連番） | 不要 | title, body, vault |
| `search_notes` | ノートを全文検索して該当箇所を返す（最大10件） | 不要 | query, vault |
| `append_note` | **既存ノートの末尾に追記**（存在しないノートには追記できない） | 不要 | path, body, vault |

### 2.4 github（GitHub 読み取り）

| アクション | 何ができる | 承認 | 主な入力 |
|---|---|---|---|
| `read_readme` | リポジトリの README 全文を取得 | 不要 | repo（省略時は既定リポジトリ） |

※ issue や PR の読み書きは未実装です（roadmap 記載の将来項目）。

### 2.5 n8n（自動化ツール n8n との連携）

| アクション | 何ができる | 承認 | 主な入力 |
|---|---|---|---|
| `trigger_webhook` | n8n のワークフローを Webhook で起動 | 不要（write扱いだが確認パネルはない） | webhook_path, payload |
| `list_workflows` | 登録済みワークフロー一覧（名前・有効/無効）を取得 | 不要 | なし |

### 2.6 llm（文章の生成・要約・変換）

| アクション | 何ができる | 承認 | 主な入力 |
|---|---|---|---|
| `generate` | テキストの要約・変換・生成。前のステップの出力を加工する時に使う | 不要 | prompt |

## 3. 複数ステップの組み立て方（オーケストレーション）

### 3.1 ステップの連結

計画は最大 **5ステップ**（環境変数 `MAX_PLAN_STEPS` で変更可）まで。あるステップの結果を次のステップに渡すには:

- `{{step1.output}}` … 1番目のステップの出力をそのまま差し込む
- `{{previous.output}}` … **直前のタスク**（前回の実行）の結果を差し込む（「さっきの結果を保存して」が動く仕組み）

例:「READMEを要約してObsidianに保存」→ ①github.read_readme → ②llm.generate（{{step1.output}}を要約）→ ③obsidian.save_note（{{step2.output}}を本文に）

安全上の上限: 書き込み系アクションは1計画あたり **3回まで**。実行時間は合計 **300秒**（超過分のステップは実行せずスキップとして記録）。失敗したステップに依存する後続ステップも自動でスキップされます。

### 3.2 タスクの分類（classifier）

タスク文のキーワードで種類を判定します（現状はルールベース。カッコ書きのタイトル部分は判定から除外される工夫あり）:

| 種類 | 判定キーワード例 | 向かうツール | 使うモデル |
|---|---|---|---|
| CODING | 実装して・リファクタ・バグを直して・.py | nachtcode | qwen-35b |
| CODE | github・リポジトリ・readme | github | qwen-35b |
| WRITE_NOTE | メモ・保存して／検索して／追記して | obsidian | gemma-31b（実体はQwen※→§5） |
| AUTOMATION | n8n・webhook・自動化 | n8n | qwen-35b |
| BROWSER | ブラウザ・webページ・スクレイピング | browser | qwen-35b |
| GENERAL | （上記いずれでもない） | ツールなし＝ただの会話 | qwen-35b |

### 3.3 計画の立て方（planner＝計画を立てる部分）

1. **高速パス**: ツール語彙を含まない雑談・質問は、計画生成を省いて直接回答（無駄なLLM呼び出しをしない)
2. **LLM計画**: Qwen にツールカタログを渡し、JSON形式の実行計画を作らせる
3. **フォールバック**: LLMの計画が解釈できない・LLM未接続のときは、キーワード分類による1ステップ計画に切り替え（CHAT画面のみ）
4. **Nacht Code（CODE画面）は例外**: 解釈失敗時はフォールバックせず**実行拒否**（推測でコードを書き換えないため）

LLMが計画に「承認済みフラグ」を勝手に書き込んでも、計画の読み取り時に**強制除去**されます（無人push・無断ブラウザ操作の防止）。

## 4. 対象ディレクトリと安全の境界線

### 4.1 CODE画面で選べる対象フォルダ

- **固定候補チップ2件**: `~/DOUNIWA` と `~/local_mlx_server`（自動スキャンはしない。存在＆安全チェックを通ったものだけ表示）
- **GitHubから選ぶ**: 自分のリポジトリ一覧から選ぶと `~/nachtcode-repos/` にクローン（取得）して対象にする（クローン済みなら再利用）
- **手入力**: 絶対パスを直接入力してもよい
- git 管理されていないフォルダは、「git管理外でも実行（バックアップ確認済み）」にチェックしない限り拒否されます（変更を巻き戻す手段がないため）

※候補に `~/local_mlx_server` が出ますが、運用ルール上ここは**聖域**（触らない約束の場所）です。選ばないでください。

### 4.2 「外に出られない」仕組み（実装として強制）

- 対象フォルダとして指定できない場所が定義済み: `/`・ホーム直下・`/etc`・`/usr`・`/System`・`/Library`・`/Applications`・`~/Library` など
- ファイル操作のたびに、パスを完全解決（`../` やシンボリックリンクという「抜け道」を展開）してから対象フォルダ配下かを検査。外なら拒否
- `run_command` だけは性質上の注意あり: 作業場所は対象フォルダに固定され全コマンド記録されますが、OSコマンドである以上、コマンド自身の副作用（キャッシュ書き込み等）の完全封じ込めは技術的に不可能です（Claude Code と同じ性質）

### 4.3 承認ゲートの全パターン

| 何をするとき | 出るもの | 承認の方式 |
|---|---|---|
| git push | プレビュー（送信先・ブランチ・コミット一覧） | 確認ボタン（UIは2段階クリック）/ CLIは y/n |
| browser の未知ドメイン | ドメイン承認パネル | 「今回だけ許可／恒久許可／拒否」の3択 |
| browser の click / fill_form | 操作内容プレビュー | 2段階クリック＋ワンタイムトークン |
| browser の submit_form | 操作内容プレビュー | 上記に加え**最終確認をもう1回**（計2回承認） |
| 許可リストへの恒久追記 | ドメイン承認パネルの「恒久許可」ボタン | 人間のボタン操作でのみ追記される |

承認フラグは**サーバー側の承認窓口だけ**が付与でき、AIが計画に書いても除去されます。
承認待ちで止まったタスクは TASKS 画面で「承認待ち」と表示され、承認後の実行は**別の記録**として追記されます（元の記録は書き換えない＝監査の正確さ優先）。

## 5. 使えるモデル（AIの頭脳）と現在の実態

登録上のモデル一覧（`app/llm/models.py`）と、.env 設定から読み取れる実態:

| 登録名 | 役割 | 実態（2026-07-26 時点の設定） |
|---|---|---|
| qwen-35b | 主力（コード・ツール系）・既定 | **実体は Qwen3.6-35B-A3B-4bit。現在稼働中の唯一のローカルモデル** |
| gemma-31b | 主力（日本語・要約系） | **設定が Qwen の実体名に向けられている**（gemma停止中の暫定措置）。つまり gemma を選んでも実際は Qwen が答える |
| gemma-26b | 軽量枠 | サーバー側停止中。選ぶと失敗して stub（ダミー応答）になる |
| llama-70b | 品質優先枠（明示指定時のみ） | 設定名 `llama-3.3-70b-mlx`。**実際に稼働しているかはサーバー側次第（コードからは確認できず）** |
| cloud-claude | クラウド予備 | **接続先URL未設定＝使えない**（選ぶと stub） |
| cloud-gemini | クラウド予備 | **接続先URL未設定＝使えない**（選ぶと stub） |

- 事実上、**すべてのタスクを Qwen3.6-35B が処理**しています
- Qwen の「思考モード」（回答前に長い独り言を出す癖）は抑制済み。タイムアウトは180秒
- クラウドモデルはコード上「機微情報を含むタスクでは使わない」方針が明記されています（現在は未接続なのでそもそも使われない）

## 6. できないこと（明示）

1. **ログイン・認証・購入（browser Lv3）は実装されていません。** パスワード入力やカード決済などの操作は、アクション自体が存在しないため、AIがどう計画しても実行経路がありません
2. **聖域には触れません。** MLXサーバー本体・プロキシ・launchd・AIVENA OS はこのシステムの管理外です（読むことすらしない設計・運用）
3. **メール送信・メッセージ送信・カレンダー操作などの機能はありません。** 外部への「送信」ができるのは n8n webhook 起動、browser の submit_form（2回承認）、git push（承認制）の3経路だけです
4. **スケジュール実行（毎朝◯時に実行など）はありません。** タスクは人間が投入したときだけ動きます
5. **頭脳がローカル Qwen 35B であることによる実務上の限界**（実測に基づく傾向。断定ではありません）:
   - 複雑・長大なコーディングタスク（多ファイルにまたがる自律開発など）は不向き。計画は最大5ステップ・書き込み3回の枠内で動くため、大きな作業は小さく分けて頼む方が確実
   - 長い文脈や会話履歴を渡すと考えが発散しやすい実測があり、システム側で履歴の渡し方を絞っています
   - 計画JSONの生成に失敗することがあり、その場合 CODE 画面は「実行拒否」で止まります（安全側に倒す設計）
6. **既存ファイルの黙った上書きはしません。** create_file は既存を上書きできず、Obsidian の save_note は新規のみ・append_note は既存のみ、と役割が分離されています

## 7. 実際に投げられるタスクの例文

すべて現在の実装で実現可能な組み合わせです（CHAT画面 / CODE画面の別を付記）。

1. **（CHAT）**「github の README を取得して、日本語で要約して、Obsidianに『リポジトリ概要』というメモで保存して」
   → github.read_readme → llm.generate → obsidian.save_note の3ステップ
2. **（CHAT）**「zenn.dev の <記事URL> を開いて内容を要約して」
   → browser.fetch_page（zenn.dev は許可リスト済みなので承認不要）→ llm.generate
3. **（CHAT）**「さっきの結果を Obsidian の『調査ログ』ノートに追記して」
   → obsidian.append_note（{{previous.output}} で直前タスクの結果を使う）
4. **（CHAT）**「Obsidianで『MLX』を検索して、見つかった内容をまとめて」
   → obsidian.search_notes → llm.generate
5. **（CHAT）**「n8n のワークフロー一覧を見せて」
   → n8n.list_workflows
6. **（CODE）**「hello.py の greet 関数に docstring を追加してテストして」
   → nachtcode.read_file → llm.generate → nachtcode.edit_file → nachtcode.run_tests
7. **（CODE）**「https://example.com を開いてページのタイトルを教えて」
   → browser.fetch_page（未知ドメインなのでドメイン承認パネル→承認後に実行）
8. **（CODE）**「変更をコミットして push して」
   → nachtcode.git_commit → nachtcode.git_push（プレビューが出て、承認ボタンを押した場合のみ push される）

- **browser の write（click等）の実運用実績**: テストは通っていますが、実サイトでの利用実績はこの棚卸しからは確認できません
